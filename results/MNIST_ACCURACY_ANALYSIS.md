# 手写数字 91.1% 瓶颈分析与优化方案

> 依据：`results/REPORT.md`、`experiments/mnist_experiments.py`、`src/neurosim_gpu/topology.py`，
> 以及本次在 `.venv` 上的诊断与消融（seed=0，10k 训练 / 2k 测试，10 epochs）。

## 1. 结论先行

91.1% 的主要限制**不是过拟合，而是欠拟合 + 输入编码容量不足**：

| 证据 | 数值 | 含义 |
|---|---|---|
| 训练精度 vs 测试精度 | 91.7% vs 90.9%（seed 0） | 差距仅 ~0.8 pt，**没有过拟合** |
| 感觉投射可学习 | 90.9% → **92.8%**（+3.1k 参数） | 收益最大，**瓶颈在输入编码** |
| 神经元 256 → 512 | 90.9% → 92.5%（+4.6k 参数） | 容量增加有效 |
| 感觉 fanout 4 → 16（参数不变） | 90.9% → 90.9% | 之前报告的 +1.0 pt 在本次未复现，**属于种子噪声** |
| 状态饱和比例 | 0.9% | **不是饱和问题**，排除该假设 |
| 感觉信号尺度 | std 0.66，|z|>3 仅 0.15% | 激活尺度合理，**排除信号过小/截断** |

因此根因排序：

1. **固定随机的感觉投射（主因）**：784 个像素只通过每个像素 4 条随机边投到 256 个神经元，
   这一层的权重从不学习。它决定了"能看到什么"，而这一层是随机的，信息在第一跳就被压缩/丢失。
2. **读出只看最后一个 tick 的状态**：8 个 tick 的中间状态被丢弃，读出层只有 2,570 个可训练参数，
   表达能力受限。
3. **训练预算偏小**：10k 样本、10 epochs、无数据增强、无学习率调度；数据量曲线到 20k 仍在上升
   （92.45%），说明模型还没吃饱数据。
4. **递归核的边际收益有限**：T=0 时 84.7%，T=8 时 91.0%，递归贡献真实但在"固定随机输入"的框架下
   受输入瓶颈约束。

## 2. 优化方案（按预期收益排序）

### 方案 A：让感觉投射可学习（最高优先级）
- **做法**：把 `learn_sensory` 设为 `True`，或直接训练稀疏投射的边权重（保持稀疏拓扑不变）。
- **预期**：+1.9 ~ +2.0 pt → **约 93%**。
- **代价**：可训练参数 4.6k → 7.7k。
- **注意**：这会改变"固定随机拓扑"的卖点。应在报告中明确：可训练的是**权重**，拓扑仍固定。

### 方案 B：多 tick 状态拼接读出（零额外递归成本）
- **做法**：读出层接收 `concat(s_1, …, s_T)`（或每个 tick 的平均），而不只用 `s_T`。
- **预期**：+0.5 ~ 1.5 pt（待验证）。读出参数随 T 线性增长，T=8 时约 2.0k×8 ≈ 18k，需要权衡，
  可用 `mean_t(s_t)` 代替以保持参数不变。
- **代价**：读出参数量增加（若用拼接）；若用均值则几乎无代价。

### 方案 C：增加神经元数（容量换精度）
- **做法**：N = 256 → 512，保持 d=8。
- **预期**：+1.5 pt（已验证 92.5%）。
- **代价**：参数 4.6k → 9.2k，单步延迟与训练时间约翻倍。

### 方案 D：训练流程改进（不改模型结构，成本最低）
- **做法**：
  - 余弦学习率调度（当前无调度）；
  - 增加 epochs（10 → 20–30），因为训练精度仍低于数据量上限；
  - 轻量数据增强（±2 px 平移、小幅旋转）——注意 §5.4 显示平移鲁棒性是弱项，增强可能直接改善它；
  - 使用全量 60k 训练集（当前只用 10k）。
- **预期**：全量数据 + 调度 + 更多 epoch 预计可达 **93–95%**，这是单项收益最大的"免费"改进。
- **代价**：训练时间增加（当前 CPU 上约 14 s/10 epochs/10k，全量 60k·20 epochs 约需数分钟）。

### 方案 E：组合（推荐的落地路径）
A + B(均值读出) + D(全量数据 + 调度 + 20 epochs)，保持 N=256、d=8、T=8。
- **预期**：约 **94–95%**，仍显著少于稠密 RNN（95.0%）的参数量（约 7.7k vs 269k）。
- 这是把"参数效率"的卖点保住的同时，把绝对精度推到接近稠密基线的做法。

## 3. 建议的验证计划

1. **先做 D**（只改配置，零代码风险）：在 `--config-json` 中设 `train_size=60000, epochs=20`，
   与当前 baseline 对比，确认数据/训练预算的上限。
2. **再做 A**：`learn_sensory=true`，3 个种子，与基线做均值 ± 标准差对比。
3. **最后做 B**：需要修改 `SparseBrain.forward` 以聚合多 tick 状态，属于代码改动，
   需补单元测试并确认 `simulation()`（PELS 路径）同步更新，避免事件路径与矩阵路径不一致。
4. 每个方案至少 3 个种子，报告均值 ± 标准差；差距 < 1 个标准差的结论不采信（沿用 REPORT.md 的口径）。

## 4. 需要注意的风险

- **拓扑卖点**：方案 A 让感觉权重可学习，会削弱"固定连接组"的表述。论文/文档需同步修改措辞。
- **PELS 一致性**：方案 B 改变读出输入后，`HybridPELSRuntime` 的 `simulation()` 路径必须同步，
   否则 §5.5 的有界误差结论不再对应同一模型。
- **种子噪声**：本次 fanout 的 +1 pt 未复现，说明小于 ~1 pt 的差异需要更多种子才能定论。
- **CPU 延迟**：更大 N / 更多 epoch 会放大训练时间，但不影响精度结论。

## 5. 未验证项（诚实声明）

- 方案 B 与方案 D 的收益是基于经验估计，**尚未在本仓库实测**，应在执行前先跑小规模验证。
- 本次消融仅用 seed=0 单点，结论方向可靠但幅度需以 3 种子均值为准。
